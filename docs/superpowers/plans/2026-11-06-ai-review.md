# AI の見直し Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** AI の答えを人があとでまとめて速く確かめ、確かめた答えを覚えて次から使い、直した行だけを再実行できるようにする。

**Architecture:** 新しい純粋な関数（指紋・手順キー・記憶・似た例・一覧の16列・再実行の CSV・目安の集計）は `src/AiReview.ps1` に置く。再生は Io の新しい口（`AiRecall`・`AiExamples`・`AiSpot`）を通して記憶と抜き取りを使い、テストでは偽物の Io で確かめる。見直しの窓は `gui/AiReview.ps1` に置く。

**Tech Stack:** Windows PowerShell 5.1、Windows Forms、既存の AI コマンド（`src/Ai.ps1`・`gui/AiServer.ps1`）

**Spec:** `docs/superpowers/specs/2026-11-06-ai-review-design.md`

## Global Constraints

- `.ps1` は ASCII・CRLF。日本語の文言は `fujikyun_ja.json` の `run.*`・`gui.*` のキーにだけ書く（キーの有無のテストは、決まった頭の名前しか調べない）。テストのファイルも ASCII にする（全角の文字は `[char]` で作る）。
- `src`・`gui` を直したら、`build\Build-FujiBundle.ps1` を実行し、続けて `node tools/build_docs.js` を実行する（dist が最新かもテストが見る）。
- テスト: `ssh win11vm 'powershell -NoProfile -ExecutionPolicy Bypass -File \\Mac\Home\Developer\RPA\RPA\tests\Invoke-FujiTest.ps1'`
- 記憶のファイル: `fujikyun_ai_answers.json`（本体と同じフォルダ）。例は手順ごとに新しい30件まで、文は先頭100字。指紋は SHA-256 の16進の先頭16文字。
- 似た例: 文字の2つ組の Jaccard 係数で上位3つ、0.1 未満は使わない。AI_CHOOSE だけ。
- 抜き取りの割合: 0〜20%、最初は 5%、`fujikyun_settings.json` の `ai.spot`。
- 一覧は16列（今の11列 ＋ `kind`・`macroId`・`key`・`hash`・`done`）。`kind` は `low`・`noLetter`・`notInSource`・`empty`・`spot`。
- 目安の帯: 0〜0.3、0.3〜0.5、0.5〜0.7、0.7〜1。
- `textVersion` 13→14、アプリの版を上げる。`commandsVersion` はそのまま。
- PowerShell の変数名は大文字小文字を区別しない（呼ぶ側の変数を覆わない名前にする）。総称の List に `@()` を付けない。

## Review Focus

1. **同じ行に AI の手順が2つある**（選ぶ・抜き出す）→ 再実行の CSV では、その行を1つにまとめる。Task 1 にテスト。
2. **記憶の答えが今の選択肢に無い**（選択肢を直した）→ 記憶を使わずに AI に聞く。Task 2 にテスト。
3. **一覧を Excel で開いたまま「済」を書こうとする** → 窓は止まらず、その件を「済にできなかった」と表示する。記憶には入れる。Task 1 にテスト。
4. **今読み込んでいる CSV が、一覧を作ったときと別のもの**（行数が足りない）→ 再実行の CSV を作らずに理由を出す。Task 1 にテスト。
5. **読ませた文に改行やカンマがある** → 指紋は改行・空白を除いて作るので、同じ文として一致する。一覧の CSV は崩れない。Task 1 にテスト。

### Task 1: 見直しの純粋な関数（`src/AiReview.ps1`）

**Files:**
- Create: `src/AiReview.ps1`
- Modify: `src/Ai.ps1`（`Add-FujiAiReviewRow` を16列にする）、`fujikyun_ja.json`（`run.aiReviewHeader` に5列を足す）、`tests/Invoke-FujiTest.ps1`

**Interfaces:**
- Produces:
  - `Get-FujiAiTextHash -Text <string>` → 16文字。`ConvertTo-FujiAiPlain`（`src/Ai.ps1`）でそろえてから SHA-256 を取る。
  - `Get-FujiAiStepKey -Cmd 'AI_CHOOSE'|'AI_EXTRACT' -MacroId <string> -Settings <IDictionary>` → 16文字。AI_CHOOSE は `macroId|name|値1|値2…`、AI_EXTRACT は `macroId|項目1|項目2…` の指紋。
  - `Read-FujiAiMemory -Directory` → `[ordered]` の辞書（手順キー → `@{ answers = 辞書（指紋 → 値の文字列、抜き出しは 項目→値 の辞書）; examples = List（@{ text; answer }）}`）。壊れていれば `fujikyun_ai_answers_broken_<時刻>.json` に控えを取り、空の辞書を返す（`$script:FujiAiMemoryNotice` に文を入れる）。
  - `Save-FujiAiMemory -Directory -Memory`（`Write-FujiFileSafely` で書く）
  - `Get-FujiAiRemembered -Memory -Key -Hash` → 答え、または `$null`
  - `Add-FujiAiRemembered -Memory -Key -Hash -Answer -ExampleText`（`ExampleText` が空でなく、答えが文字列なら、例に足す。同じ指紋の古い例は除き、新しい30件までにする）
  - `Select-FujiAiExample -Memory -Key -Source -Max 3` → List（@{ text; answer }）。Jaccard が 0.1 以上のものを、高い順に並べる。
  - `Read-FujiAiReviewItem -Directory -MacroId -Days -Now` → List。1件は `@{ File; Line; Old（11列なら $true）; Time; Macro; MacroId; Step; Row; Command; Name; Source; Answer; P; Probs; Reason; Kind; Key; Hash; Done }`。`ai_review_<日付>.csv` と `_N` 付きのファイルを、`Days` 日分読む。11列の行は `Old` にする。
  - `Set-FujiAiReviewDone -Item -Time <string>` → `$true` / `$false`（ファイルが使用中なら `$false`。その行の `done` 列だけを書き換え、ほかの行は変えない）
  - `New-FujiAiRerunCsv -Header <string[]|$null> -Rows <IList（@{ No; Data }）> -RowNos <int[]>` → `@{ Text; Count; Error }`。`Error` は `run.aiRerunNoRows`・`run.aiRerunMissing`（行番号が無い）・`run.aiRerunNoCsv` のどれか。行番号は重複を除き、昇順に並べる。形は `ConvertTo-FujiErrorCsv` と同じで、元の列 ＋ 元データ行No ＋ 空のエラー列 ＋ 空の時刻列。
  - `Get-FujiAiReviewSummary -Items` → `@{ SpotTotal; SpotKept; Bands = 4件（@{ From; To; Total; Kept }）}`。`Kept` は、済の件のうち、答えが AI の答えのままだった数。`Items` には `Final`（人が選んだ答え）がある件だけを数える。
- Consumes: `ConvertTo-FujiAiPlain`・`ConvertTo-FujiCsvText`・`ConvertFrom-FujiCsv`・`Read-FujiCsvText`・`Write-FujiFileSafely`・`Test-FujiFileBusy`

- [ ] **Step 1: Write the failing tests**（「AI: prompts…」の節の後ろに `# AI review` の節を足す）
  - `ai review: hash ignores width, spaces, newlines`: `Get-FujiAiTextHash ("a b`nc")` と `Get-FujiAiTextHash ([char]0xFF41 + 'bc')` が等しく、長さは16。
  - `ai review: step key changes with option order`: 選択肢 `"x`ny"` と `"y`nx"` で、キーが違う。
  - `ai review: memory round trip and cap 30`: 例を35件足して保存し、読み直すと 30 件で、最も古い5件が無い。
  - `ai review: broken memory file is kept aside`: 壊れた JSON を置いて読むと、空になり、`fujikyun_ai_answers_broken_*.json` が1つある。
  - `ai review: similar examples top 3, below 0.1 left out`: 例を5件（似たもの3件、無関係2件）置くと、似た3件が高い順に返る。
  - `ai review: 16 columns written, 11-column file read as old`: 11列だけの古いファイルの行が `Old=$true` になり、新しい行は16列になる。
  - `ai review: done written to that line only`: `done` を書くと、その行の `done` 列だけ時刻になり、ほかの行のバイトは変わらない。
  - `ai review: done on a locked file returns false`（Review Focus 3）: FileShare None で開いたまま `Set-FujiAiReviewDone` を呼ぶと `$false`。
  - `ai review: rerun csv merges rows, keeps original numbers`（Review Focus 1）: RowNos `@(3,1,3)` で、2行（1・3）になり、元データ行No の列は `1`・`3`。
  - `ai review: rerun csv refuses missing rows`（Review Focus 4）: Rows が2件しか無いのに RowNos が `@(5)` だと、`Error` が `run.aiRerunMissing` の文。
  - `ai review: source with comma and newline hashes the same and CSV stays whole`（Review Focus 5）
  - `ai review: summary bands and spot`: 抜き取り2件（1件は直した）と、帯ごとの件数が期待どおりになる。
- [ ] **Step 2: Run and see them fail**（`Get-FujiAiTextHash` が無いので失敗する）
- [ ] **Step 3: Implement**（`Add-FujiAiReviewRow` は、Row の `kind`・`macroId`・`key`・`hash`・`done` を後ろに書く。無いキーは空にする）
- [ ] **Step 4: Build and run; failures 0**
- [ ] **Step 5: Commit** — `feat(ai-review): hash, step key, memory, similar examples, 16-column list, rerun csv`

### Task 2: 再生で記憶・似た例・抜き取りを使う（`src/Runner.ps1`）

**Files:**
- Modify: `src/Runner.ps1`（`Invoke-FujiAiChoose`・`Invoke-FujiAiExtract`・`Add-FujiRunAiReview`・Io の説明のコメント）、`src/Ai.ps1`（`New-FujiAiChooseBody` に `-Examples`）、`tests/Invoke-FujiTest.ps1`（偽物の Io に `AiRecall`・`AiExamples`・`AiSpot`）、`fujikyun_ja.json`

**Interfaces:**
- Consumes: `Get-FujiAiTextHash`・`Get-FujiAiStepKey`（Task 1）
- Produces:
  - Io に足す口:
    - `AiRecall {Key; Hash}` → 記憶の答え、または `$null`
    - `AiExamples {Key; Source}` → 例の List
    - `AiSpot {}` → bool
  - `New-FujiAiChooseBody -Question -Options -Source [-Examples <IList>]`: 例があれば、system の最後に `run.aiExamplesHead` の行と `- <text> -> <記号>` を足す。例の答えが今の選択肢に無いものは足さない。
  - 一覧の行（`AiReview` に渡すもの）に、`kind`・`macroId`・`key`・`hash` を足す。
  - ログの文言: `run.aiRecalled`（記憶から: 変数・値）、`run.aiExamplesUsed`（例 n 件）

- [ ] **Step 1: Write the failing tests**（「AI commands (fake AiChat…)」の節）
  - `ai run: remembered answer used, AI not asked`: `AiRecall` が `garbage` を返すと、`AiBodies.Count -eq 0` で、`Vars['desk'] -eq 'garbage'`・`_確率 -eq '1.00'`。ログに `run.aiRecalled` の文がある。
  - `ai run: remembered answer not in the options asks the AI`（Review Focus 2）: `AiRecall` が `old` を返すと、AI に聞く。
  - `ai run: extract remembered`: `AiRecall` が `@{ name = 'Nakamura Sakura'; phone = '1' }` を返すと、AI に聞かずに両方が入る。
  - `ai run: examples put in the prompt`: `AiExamples` が2件返すと、system に2行足され、ログに `run.aiExamplesUsed` の文がある。
  - `ai run: spot check writes a review row and keeps the answer`: 確率0.9、`AiSpot` が真なら、答えはそのままで、一覧に `kind -eq 'spot'` の1行がある。
  - `ai run: no spot check for remembered answers`: 記憶から答えたときは、`AiSpot` を呼ばない。
  - `ai run: review rows carry kind, macroId, key, hash`: しきい値未満の行の `kind -eq 'low'`、`macroId -eq 'main'`、`hash` の長さ16。
- [ ] **Step 2: Run and see them fail**
- [ ] **Step 3: Implement**（順番は、文が空 → 記憶 → 例 → AI に聞く → しきい値と抜き取り。抜き取りは、しきい値以上で、記憶から答えていないときだけ `AiSpot` を呼ぶ）
- [ ] **Step 4: Build and run; failures 0**
- [ ] **Step 5: Commit** — `feat(ai-review): runner uses remembered answers, similar examples, spot checks`
