# ふじキュンの AI コマンド（AIに選んでもらう・AIに抜き出してもらう）設計

- 日付: 2026-11-05
- 状態: 設計（ユーザーの了承済みの内容をまとめたもの）
- 前提の試験: `tools/llm-bench/README.md`（PR #54〜#74）、`tools/llm-bench/agent/README.md`（PR #73）

## 1. 目的と範囲

職場の PC（LLM の API は使えない、GPU なし、PowerShell 5.1）で、小さな LLM を使ってマクロの中の「1手の判断」と「抜き出し」をさせる。

- 作るもの: コマンド2つ（`AI_CHOOSE`・`AI_EXTRACT`）、AI の置き場所の設定と C: への写し、llama-server の起動と停止、共有ドライブに置くための `ai-setup.bat`、テンプレート2つ、説明書の追記。
- 作らないもの:
  - AI に段取りを任せること。試験では 3/12 だった（`tools/llm-bench/agent/README.md`）。段取りはマクロが持ち、AI には決まった問いを1つだけ任せる。
  - 思わぬ画面が出たときに、自動で AI に聞くしくみ。今回はテンプレートでマクロに組み込む。
  - AI の写しを自動で消すこと。設定の「写しを消す」ボタンだけ。

成功の条件:

- 職場の PC で、2つのコマンドを入れたマクロが最後まで動く。
  - 選ぶ: 1問 1〜3秒（最初の1問は約5秒）。
  - 抜き出す: 1問 約4秒。
- AI を使わない人とマクロには、何も影響しない（起動時間・メモリ・ファイル）。

## 2. 使うもの

| もの | 版 | 根拠 |
|---|---|---|
| モデル | Qwen3.5-2B（Q4_K_M、1,312,164,416 バイト、SHA-256 `e85e87a1ba5ca5d90aca625b300a24de2bbd808fd572a5080d8a1ce66f648448`）、Apache-2.0 | ユーザーの決定（2026-11-05）。VM と職場の PC の結果は `tools/llm-bench/README.md` |

## 3. 全体の形と配り方

### 3.1 課の共有ドライブ（読むだけ）

```
<共有ドライブ>\AI\
  llama-x64\        llama.cpp b12063（x64）
  qwen35-q4.gguf    モデル
  ai.json           版・ファイルの一覧・SHA-256・llama-server に渡す設定
```

`ai.json` の例（値は形を示すためのもの）:

```json
{
  "aiVersion": 1,
  "model": "qwen35-q4.gguf",
  "files": { "qwen35-q4.gguf": { "size": 1312164416, "sha256": "e85e87a1..." }, "llama-x64/llama-server.exe": { "size": 0, "sha256": "..." } },
  "serverArgs": "-c 4096 -t 8 --cache-ram 0 -ctxcp 4 -np 1 --no-repack --jinja"
}
```

### 3.2 置く人が1回だけすること（`ai-setup.bat`）

- base64 の部品（llama の zip と、モデルの19個）を戻し、共有ドライブにこのフォルダと `ai.json` を作る。
- 部品は1つずつ SHA-256 を照らし、合わないものは名前を出す（`llm-speed.ps1` と同じしくみ）。
- 部品は GitHub の別のブランチに置く（master には入れない。`llm-model-qwen35` と同じ扱い）。

### 3.3 各自のふじキュン

- 設定に「AI の置き場所」（共有ドライブの `AI` フォルダ）を足す。初めて AI のコマンドを使うときに未設定なら、その場でフォルダを選ばせる。設定は `fujikyun_settings.json` に保存する。
- 写し先は `%LOCALAPPDATA%\fujikyun\ai\` にする。職場の PC で、再起動のあとも残ることを確認済み（local-check、2026-11-05）。
- 写すのは、写しが無いとき、または共有ドライブの `ai.json` の `aiVersion` が写しと違うとき。
  - いったん `*.part` に写し、SHA-256 が合ってから名前を変える（途中で止まっても、壊れた写しが残らない）。
  - 写す前に C: の空きを確かめ、2GB 未満なら写さずに理由を出す。
  - 写すあいだは、進み具合と「やめる」を出す（職場の PC で約1分半）。
- 毎回の起動では、写しの SHA-256 は照らさない（1.3GB の計算に時間がかかるため）。ファイルの大きさと `aiVersion` だけを見る。SHA-256 は写した直後と、設定の「試しに聞く」で照らす。
- 各自のマクロ・ログ・確認用の一覧は、これまでどおり本体と同じフォルダに置く（個人用ドライブに本体を置けば、他の人からは読めない）。

### 3.4 llama-server の起動と停止

- 起動: 再生中に AI のコマンドが初めて来たとき、C: の写しで起動する（約6秒）。
  - 起動の前に空きメモリを確かめ、1GB 未満なら起動せずに理由を出す（「セキュアブラウザなどを閉じると空きます」）。
  - ポートは 127.0.0.1 の空いているものを探して使う。
  - `/health` が 200 を返すまで最大60秒待つ。
  - プロセス番号を `fujikyun_logs\llama-server.pid` に書く。
- 停止: 再生が終わったとき（正常・エラー・停止のどれでも）と、ふじキュンを閉じるとき。
- 次に起動したとき、`llama-server.pid` のプロセスが llama-server のまま残っていれば止める。
- llama-server の出力（stderr）は `fujikyun_logs\llama-server_YYYY-MM-DD.log` に残し、古いものはほかのログと同じ期間で消す。

## 4. コマンド

### 4.1 AIに選んでもらう（`AI_CHOOSE`）

| 欄（id） | 中身 | 最初の値 |
|---|---|---|
| name | 答えを入れる変数名 | （空） |
| src | 読ませる文（差し込み可） | （空） |
| question | 何を選ぶか（問いの文、差し込み可） | （空） |
| options | 選択肢。1行に1つ、`値` か `値: 説明`。2〜10個 | （空） |
| threshold | 自信のしきい値（0〜1） | 0.5 |
| low | 自信が低いとき: `REVIEW`（あとで確認に回す）・`ASK`（人に選んでもらう）・`STOP`（止める）・`USE`（そのまま使う） | `REVIEW` |
| unknown | わからないときの値 | `不明` |

組み立て（system）:

```
あなたは市役所の職員を手伝います。{question}。答えは記号1文字だけです。
A: {値1}（{説明1}）
B: {値2}
...
```

user には `src` を入れる。`src` が3000字を超えるときは先頭3000字で切り、切ったことをログに残す。

問い合わせ: `/v1/chat/completions` に `max_tokens 1`・`temperature 0`・`logprobs true`・`top_logprobs 20`・`chat_template_kwargs.enable_thinking false` を送る。上位のトークンのうち記号（A〜J）に当たるものの確率を足し合わせ、選択肢の中で割り直す（`tools/llm-bench/Invoke-LlmDecide.ps1` と同じ）。

結果:

- 確率がしきい値以上: `{{$name}}` に値を入れ、`{{$name_確率}}` に確率（小数2桁）を入れる。
- しきい値未満:
  - `REVIEW`: `{{$name}}` に `unknown` を入れ、確認用の一覧に1行書き、続ける。
  - `ASK`: 再生を止めて窓を出す。AI の答えを選んだ状態で選択肢を並べ、人が選んだら続ける。
  - `STOP`: エラーにする。
  - `USE`: そのまま値を入れる。
- 記号の確率の合計が 0.5 未満（AI が記号で答えなかった）ときは、しきい値未満と同じ扱いにする。

### 4.2 AIに抜き出してもらう（`AI_EXTRACT`）

| 欄（id） | 中身 | 最初の値 |
|---|---|---|
| src | 読ませる文（差し込み可） | （空） |
| items | 抜き出す項目。1行に1つ、`変数名` か `変数名: 説明`。1〜10個 | （空） |
| note | 指示を足す（任意、差し込み可） | （空） |
| strict | 文に無い値は入れない（`ON`・`OFF`） | `ON` |

組み立て（system）: 「文から次の項目を、書いてあるとおりに写して JSON で答えます。書いていない項目は空の文字列にします。」に項目の一覧と `note` を足す。

問い合わせ: `response_format` に JSON schema を指定する（項目ごとに `type: string`・`maxLength 100`、全項目 required、`additionalProperties false`）。`temperature 0`、`max_tokens` は項目の数 × 60（最大 600）、`enable_thinking false`。

結果:

- 各項目の値を `{{$変数名}}` に入れる（前後の空白は消す）。
- `strict` が `ON` のとき、値（NFKC にし、空白を除いたもの）が元の文（同じく直したもの）に含まれなければ、空にして確認用の一覧に1行書く。
- 日付の書き換えは AI にさせない（試験で、写させてから直すほうが正確だった。`tools/llm-bench/README.md` の V2）。

### 4.3 共通

- エラーにするとき: llama-server が起動しない、答えが JSON として読めない、60秒で返ってこない、置き場所や写しが無い、空きメモリが足りない。どれも「エラーを受け止める」「やり直す」で扱える。メッセージには理由と直し方を書く。
- ログ（実行記録）: コマンド、答え（選ぶ: 値と確率、抜き出す: 項目名と値が入ったかどうか）、かかった時間、プロンプトのトークン数、使い回したトークン数を残す。読ませた文は残さない。
- 確認用の一覧 `fujikyun_logs\ai_review_YYYY-MM-DD.csv`（UTF-8、BOM 付き、Excel で開ける）の列:
  - 時刻、マクロ名、手順の番号、CSV の行番号
  - コマンド、変数名
  - 読ませた文の先頭100字
  - AI の答え、確率、ほかの選択肢の確率（`値=確率` を `;` でつないだもの）
  - 理由（`しきい値未満`・`記号で答えなかった`・`文に無い値`）
- 個人の情報: 確認用の一覧には読ませた文の先頭100字が残る。説明書に、置き場所（本体と同じフォルダ）と、古いものを消す期間（ほかのログと同じ）を書く。
- 再生中の「停止」は、AI の答えが返った時点で効く。

## 5. 画面

- 設定に「AI」の欄:
  - 置き場所（フォルダを選ぶ）
  - 状態（共有ドライブの `aiVersion`、写しの `aiVersion`、SHA-256 が合っているか）
  - 「今すぐ写す」「写しを消す」「試しに聞く」（起動・選ぶ1問・停止を通し、時間を出す）
- 写す窓: 進み具合（MB と %）・「やめる」。
- `ASK` のときの窓: 問い・読ませた文（先頭500字）・選択肢（AI の答えを選んだ状態、各選択肢の確率つき）・「これにする」「止める」。
- 環境チェック: AI の置き場所、写しの版、空きメモリ、AVX2 の有無、C: の空き。
- 手順の編集画面: 選択肢と項目は複数行の入力欄にする。選択肢が11個以上なら保存の前に知らせる。

## 6. テスト

自動（`tests/golden.json` と `tests/Invoke-FujiTest.ps1`、モデルは使わない）:

- 選択肢と項目の読み取り（`値: 説明`、全角のコロン、空行、11個以上）
- system の組み立て
- 確率の読み取り（llama-server の応答を模した JSON。記号の前の空白、記号以外のトークン、合計が 0.5 未満）
- しきい値と `low` ごとの動き
- `strict` の判定（全角半角・空白の違い、文に無い値）
- 確認用の一覧の書き込み（列、BOM、追記）
- `ai.json` の読み取りと版の比較、写しの要否の判定

VM（本物の llama-server、x64 版、節約の設定）:

- 2つのコマンドを入れたマクロ（テンプレート2つ）を最後まで流す。
- 写す（共有ドライブの代わりに `\\Mac\Home` の下）、途中でやめる、版が変わったら写し直す。
- エラー: 置き場所の誤り、メモリ不足（しきい値を変えてまねる）、時間切れ（短い時間切れでまねる）、llama-server の残りの片付け。
- 画面（設定の AI の欄、写す窓、`ASK` の窓）を、vmrun.sh の画面撮影で確かめる。

職場の PC（ユーザーが戻ってから）: `ai-setup.bat` で共有ドライブに置き、テンプレートのマクロを流して、時間とメモリを確かめる。
